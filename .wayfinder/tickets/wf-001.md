## Question

Inside an ALPINE/CANVAS FIELD (ImageLabel blade + Livewire, not a Filament form), what is the cheapest search plumbing for a debounced autocomplete over several morphable model classes?

Options to weigh, with known gotchas:
- native Filament form Select (getSearchResultsUsing) embedded in the same Livewire component
- custom Livewire search endpoint/method on the ImageLabel component + Alpine combobox in the blade
- Filament Actions (Attach/-style modal with its own form/table) reusing getSearchResults
- Spatie/laravel-query-builder-free naive LIKE search vs full-text needs

Constraints: no new hard dependency unless justified; must work inside a Filament form field component; must support N allow-listed model classes with a per-class display column; package already has alpine + annotorious in the bundle.

## Answer

Researched against installed vendor sources: **Filament v5.9.0, Livewire v4.4.6** (composer.lock). All line refs verified in working tree.

### 1. What the repo already has

- **State round-trip.** The canvas Alpine root live-entangles the field state: `state: $wire.entangle('{{ $getStatePath() }}').live` (image-labeler.blade.php:10). Shapes are `{id, target, label, color}`; `metaCache` keeps label/color across canvas delete→undo (blade:20, 121, 142). A `$watch('state')` (blade:170–181) syncs any *server-side* state change back into the canvas — the server→canvas push path already exists.
- **Client→server RPC from a custom field.** `$wire.call('mountAction', 'autoAnnotate', [], { schemaComponent: '{{ $field->getKey() }}' })` (blade:388) calls the field action registered via `registerActions` in `ImageLabel::setUp()` (src/Forms/Components/ImageLabel.php:54–57) and gets a JSON array back — no re-render. The field-keyed RPC channel to *any* host Livewire component is therefore already proven in this package.
- **Server→client events.** `Livewire.on('image-labeler-update-url', …)` (blade:199–205) is an existing event-in path.
- **Frontend deps.** package.json: only `@annotorious/annotorious ^3.9.3` + dev `esbuild`/`prettier`. **No Alpine, no Tailwind, no select/combobox lib** — Alpine/Livewire come from the Filament host. `resources/js/index.js` only wraps Annotorious onto `window.Annotorious`. The ServiceProvider registers no Livewire components (src/FilamentImageLabelerServiceProvider.php:34–60).
- **Autocomplete-ish UI: none.** Label editing is a plain `x-filament::input type="text"` (blade:719–726). No `datalist`, no dropdown anywhere in resources/.

### 2. Filament 5 native options (verified in vendor/)

**a) Select with `getSearchResultsUsing`** — vendor/filament/forms/src/Components/Select.php:487 (setter), :710 (`getSearchResults`), :734 (`getSearchResultsForJs`, marked `#[ExposedLivewireMethod]` + `#[Renderless]` — `Renderless` is `Livewire\Attributes\Renderless`, Select.php:42; the attribute class is vendor/filament/support/src/Components/Attributes/ExposedLivewireMethod.php:8).
- Transport: the combobox JS (`selectFormComponent`, loaded via `x-load` from filament/forms assets, Select.php:1951) calls `Livewire.fireAction($wire.__instance, 'callSchemaComponentMethod', [key, 'getSearchResultsForJs', {search}], {async:true})` (Select.php:1979–1986).
- Host side: `InteractsWithSchemas::callSchemaComponentMethod` (vendor/filament/schemas/src/Concerns/InteractsWithSchemas.php:83–125) resolves the component by key, refuses methods not marked `#[ExposedLivewireMethod]` (:96–100), and skips the DOM re-render for `#[Renderless]` (:105).
- **Debounce is built in**: `searchDebounce`, default 1000 ms, `->searchDebounce(ms)` (forms/src/Components/Concerns/CanBeSearchable.php:16, 47).
- **Embedding inside a custom field blade works mechanically**: any `Component` supports a child schema (`HasChildComponents::schema()` :72, `getChildSchema()` :101 — vendor/filament/schemas/src/Components/Concerns/HasChildComponents.php); field views receive the field's public methods as closures (ViewComponent::extractPublicMethods, vendor/filament/support/src/Components/ViewComponent.php:74–78), so `{{ $getChildSchema() }}` is callable in image-labeler.blade.php exactly like schemas/resources/views/components/fieldset.blade.php does; key lookup recurses child schemas (schemas HasComponents.php:184–211).
- **State gotcha (verified)**: a plain Field's child schema has no container state path, so a nested `Select::make('x')` binds the *sibling* `data.x` — not `data.shapes.x` (Components/Concerns/HasState.php:721–745). No collision with the entangled shape array, but it pollutes host form data → must be `->dehydrated(false)`, and getting the picked value into the Alpine label needs an extra `live()`/entangle round-trip.
- **MorphToSelect** (forms/src/Components/MorphToSelect.php:74–165) is the native heterogeneous-classes pattern: type Select + searchable key Select whose `getSearchResultsUsing`/`getOptionLabelUsing` delegate per selected type (:118–121). But `getRelationship()` (:233–244) throws `LogicException` unless the record has a real `MorphTo` relation — not usable as-is for an ad-hoc picker; it is a **pattern to copy**, not a component to instantiate.

**b) Field Action with modal + schema** — `Action::schema()/form()` (vendor/filament/actions/src/Concerns/HasSchema.php:26, 128). Register via `registerActions` (already used). Opening it is *exactly* the call the repo already makes (blade:388) — native field JS does the same: `$wire.mountAction(name, args, { schemaComponent: key })` (forms/resources/js/components/rich-editor.js:92–106; builder block-picker.blade.php:122). Modal markup: one `<x-filament-actions::modals />` stack per Livewire component, guarded by `hasActionsModalRendered` (actions/resources/views/components/modals.blade.php:5–21; InteractsWithActions.php:91), updated via `wire:partial="action-modals"`; the stack is in the standard host view (forms stubs/LivewireFormView.stub:10) and a defensive include inside our field blade is a no-op when the host already rendered it. **State risk: none** — action form state lives namespaced under `mountedActions`, never touches `data.*`. `ModalTableSelect` (forms/src/Components/ModalTableSelect.php:41, registers its select Action in setUp :76–80) is vendor proof that a *field* can drive modal actions. (AttachAction itself lives in filament/filament, not installed here, but it is this same Select+getSearchResultsUsing plumbing.)

**c) LivewireField** — vendor/filament/forms/src/Components/LivewireField.php: any registered Livewire child component embedded as a Field via `Livewire::mount(...)` (:91), auto-passing `record` + a `wire:model` state path + custom `data` (:68–83). The dedicated-child-component route: needs `Livewire::component()` registration in the provider (none today) and cross-component state handling; result still has to reach the Alpine canvas via an event.

**d) Headless combobox** — none. Searched filament/support and filament/forms view/JS inventories: the only combobox is Select's internal `selectFormComponent` asset; there is no public headless dropdown/autocomplete API to reuse.

**e) Fan-out baseline & full-text** — Filament's own default search is plain LIKE: `applySearchConstraint` + `generate_search_term_expression` (Select.php:1012–1015) plus `optionsLimit` (:1020–1026). Filament itself never uses DB full-text for pickers; a `UNION`/full-text layer across N unrelated tables has no native support anywhere in vendor/. N sequential indexed-LIKE queries with per-class limits is the framework-blessed baseline.

### 3. Custom route (verified feasible)

A public `searchLinkables(string $search)` on **ImageLabel itself**, annotated `#[ExposedLivewireMethod]` (+ `#[Renderless]`), is callable from Alpine with zero host cooperation via the very RPC that Select uses:
`$wire.call('callSchemaComponentMethod', '{{ $field->getKey() }}', 'searchLinkables', [{ search: term }])` — resolution and guards at InteractsWithSchemas.php:83–125 / :336–345; `getKey()` is already proven field-addressable in this repo (blade:388 + mountAction schemaComponent). Debounce for free via Alpine's native `x-on:input.debounce.300ms`. N-class fan-out: loop allow-listed `class => display-closure` config, one `where(col,'LIKE',"%$term%")->limit(k)` per class, merge into grouped results. The only genuinely new work is the dropdown markup itself (keyboard nav + ARIA) — no JS-build dependency needed, Alpine is host-provided.

### 4. Installed packages usable for search

composer.json require: `spatie/laravel-package-tools` only (asset publishing, not search); no query-builder/search packages in require or require-dev. Nothing already installed serves this; nothing new is needed — per the no-new-hard-dependency constraint.

### Recommendation table

| Option | Search UI | Debounce | Server plumbing | State collision risk | New code | Host requirements |
|---|---|---|---|---|---|---|
| A. Select in field child schema (same form) | native combobox | built-in (300–1000 ms configurable) | zero — reuses `getSearchResultsForJs` RPC | sibling `data.<name>` keys; needs `dehydrated(false)` + value back into Alpine | schema config only | none |
| B. **Field Action modal + Select schema** (MorphToSelect pattern, no relation) | native combobox in modal | built-in | zero — same RPC, `mountedActions`-scoped | **none** | one Action + per-type search closures + one dispatch/listener pair | action-modals stack (standard host views have it; defensive include is no-op-safe) |
| C. `#[ExposedLivewireMethod]` on ImageLabel + hand-rolled Alpine combobox | custom inline dropdown | Alpine `.debounce` | one annotated method, renderless, same proven RPC | none (no Livewire state) | method (~40 lines) + dropdown markup/a11y (~60 lines) | none |
| D. Dedicated child Livewire component | custom | `wire:model.live.debounce` | own public method | none (isolated) | component + provider registration + cross-component event | Livewire component registration |
| E. Full-text / query-builder | — | — | — | — | rejected: no vendor precedent (Filament baseline is LIKE, see 2e), no installed package, N-table UNION cost with no benefit at picker scale | — |

**Recommended: B** — a searchable `Select` (either one Select fanning out over the allow-list with `class::id` values, or a copy of the MorphToSelect type+key two-Select pattern per N classes) hosted in a **field Action modal** registered via `registerActions`.

**Why**: it reuses every expensive piece — Filament's combobox JS, debounced renderless search RPC, modal stack, validation — adds zero form-state surface (mountedActions namespacing means no collision with the `data.shapes` entangle, unlike A), needs no new dependency, no npm code, no provider changes, and every plumbing seam it depends on is *already exercised by this package* (`mountAction` + `schemaComponent` at blade:388; server→canvas sync via `$watch`/events at blade:170–205). C is the fallback if the later grilling rejects a modal (same RPC, but pays a hand-built combobox); A is strictly dominated by B (same UI for less isolation).
