## Question

Developer-facing shape of `linkableTo()`. Round-1 settled it's a per-field allow-list of morphables — now make it precise:

- `linkableTo([Person::class, Building::class])` — array of class strings, or richer entries (class + label + searchable columns + display fn)?
- per-type display: closure vs convention (first of `name`/`title` column fallback?) — Person "first last" vs Building name, user flagged this
- searchable columns per type (default = display column?)
- creating a new record from the editor reuses "the record's own form" — Filament resource form? schema provided per type? optional capability per field (`->allowEntityCreation()`)? which fields carry over into the new record (image? none?)
- type label shown to end users (i18n: `__('…')` key per type vs derived from model)

## Facts (vendor research 2026-10-07, Filament 5.9 / Livewire 4.4)

- Filament v5 Select = own JS (support/resources/js/utilities/select.js), no Choices/TomSelect; supports one-level optgroups (`value => ['label','options'=>[...]]`, Select.php:151-158) but NO per-option icon/secondary slots (only `->allowHtml()` innerHTML escape hatch).
- A (embedded Select) rejected: `Field` lacks `HasChildComponents` (no vendor precedent of a field rendering a child *input* outside repeatables), binds sibling `data.<name>` path, x-if destroys init, needs dehydrated(false) gymnastics.
- C viable & cheaper: `#[ExposedLivewireMethod]` (`Filament\Support\Components\Attributes`) on any schema Component incl. Fields; `callSchemaComponentMethod` resolves field by key, `#[Renderless]` skips re-render, returns JSON via Promise (InteractsWithSchemas.php:83-127; proven pattern at image-labeler.blade.php:388). Full template control in Alpine → optgroups + rich rows free.
- Heterogeneous values fine: Select values are opaque strings (`Person:42` style); `getOptionLabelUsing` decodes for hydrate (Select.php:466, 572-618).
- `filament/filament` NOT a dependency (suggest only); `Filament\Actions\CreateAction` is resource-free: `->model(Foo::class)->schema([...])` on any HasActions+HasSchemas host — our field qualifies. Developer supplies form schema (may reuse their resource's form closure).

## Answer

Grilling 2026-10-07. Q1–Q5 explicit; Q6 recorded as the recommendation (no objection) — field-local definitions, global registry graduates to fog, reject-able in one word.

- **Entry shape:** per-type descriptor objects passed to `ImageLabel::linkableTo([...])` (name = wf-004 vocabulary question). Chainable config, field-local.
- **Display:** convention fallback — first present of `name`, `title`, else `#id`; `->display(fn (Model) => …)` closure overrides (Person "first last" always uses closure).
- **Searchable columns:** `->searchBy([...])` required whenever a display closure is set (we never guess which columns it reads); defaults to the convention display column otherwise. Fail loud at dev time, not runtime.
- **Type label:** humanized class basename by default ("Person"); `->typeLabel(__('…'))` override for i18n; used for result group headers/badges.
- **Create-record:** per-type opt-in `->creatable(schema: fn)` — developer hands a form schema (may reuse their Filament resource's form closure). Modal via resource-free `CreateAction` (modal OK here: it's a form, not the picker — wf-002 banned only the modal *picker*). New record auto-binds to the active shape.
- **Scope:** definitions live on the field; no global registry in v1.

Consequence for picker internals (from Facts above): exposed renderless `searchLinkables` on ImageLabel fans out per type over `searchBy` columns with LIKE + per-class limit; returns `value: "Class:id"` + display + type label; combobox owns grouping/rich-row templates (C per wf-001 facts).
