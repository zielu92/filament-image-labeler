## Question

Auto-annotation methods may report that a found shape corresponds to a known record (nullable). Decide the payload + apply semantics:

- AnnotationSuggestion: add static `::make(label, geometry, entity: [type,id]?)` vs a value object `EntityRef`? (keep the package defining *that* it happens and *what shape the answer has*, never how it thinks — CONTEXT.md)
- validation at the boundary: suggestion referencing a class outside the field's `linkableTo()` allow-list — drop link, keep suggestion, or reject whole suggestion?
- Apply: linked suggestions land as ordinary shapes WITH the binding; does a model-supplied entity override the user's manual binding for a reused shape id? (Apply creates new shape ids per run? check current pending-apply flow)
- on-load annotation path: same payload?

## Answer

Grilling 2026-10-08.

- **Payload:** `AnnotationSuggestion` gains `entity: EntityRef | array{type,id} | null` — constructor param, `fromArray` key, and factory helper argument. `EntityRef` = tiny readonly VO (type + id) with `::fromArray`; both forms accepted per developer taste. No Eloquent-Model union (rejected — package resolves refs by convention, a live model invites unsaved instances). `toPending()` emits `entity: {type, id} | null` per pending item.
- **Boundary (allow-list miss / dead record):** drop the link, keep the shape, silent. Field validates suggestion entities against its `linkableTo()` list in `performAutoAnnotate`; no existence queries at suggestion time — dead refs already covered by wf-005 (render anyway) + wf-006 (basename-fallback chip).
- **Apply seeding:** empty-label suggestion with an entity gets the label seeded from the display string on Apply (wf-002 rule travels with the shape, not the entry point). Existing labels never overwritten.

Stated from facts, not asked: Apply always mints fresh UUIDs (`toPending`, AnnotationSuggestion.php:87), so a suggestion can never override a manual binding — distinct shapes. On-load and button share `performAutoAnnotate` → identical payload automatically.
