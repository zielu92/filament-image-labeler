## Question

wf-002 settled: entity renders as ITS OWN marker in the Details panel; label text (auto-seeded from the record display) becomes the ordinary grouping label. Consequence to settle: the Labels panel — the list of distinct labels — would now list record display strings like any other label ("Jan Kowalski", "Wrocław Tower"), because grouping is by label string.

Decide:
- Labels panel: entity-derived labels shown plain (group = label, uniform), or tagged/distinguished (icon? separate section?)?
- Colors: `defaultColorFor(label)` hashes the label string — entity rows get colors the same way, or color keyed to entity type?
- Two shapes bound to different records that happen to share a display string ("Jan Kowalski" the person vs the building) — merged into one label group? Is that acceptable or must entity-bound labels be unique per entity?

## Answer

Grilling 2026-10-08 — both recommendations accepted.

- **Labels panel rows stay plain.** Rows remain pure label groups — no type icons, no "Entities" section. Any row-level entity marker would lie in mixed groups (linked + unlinked shapes sharing a label string), and the seed/rename flow makes "derived-from-entity" a property of history, not of the current group. Entity identity lives only at the shape level: the Details-panel entity chip.
- **Display-string collisions accepted.** Grouping and color follow the label string exactly as today ("Jan Kowalski" person + hand-typed "Jan Kowalski" = one row, one hash-color). No seed suffixing, no rename warnings. Emergent property kept: same entity's seeded string hashes to the same color across photos.
