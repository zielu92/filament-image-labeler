## Question

Contract, guards and staleness settled by wf2-002. Remaining editor-side spec:

- **Affordance**: chip as a whole clickable, or a trailing view-icon (arrow-top-right) beside the unlink `×`? Hover/focus styles; what shows when `visible()` true but no url (modal-only chip)?
- **Read-only canvas**: linked+visible shape click → run its action (navigate or… modal on a read-only field — allowed?); unlinked/hidden shapes keep current behavior? Cursor hint (pointer vs default) for actionable shapes?
- **Action name collision**: internal registered name `openLinkedEntity` vs per-type names — could two linkable types need different modals? One action per FIELD (template) — the record tells the developer what to render. Confirm single template is enough (vs `->entityAction()` per type).
- **A11y**: chip focusable/Enter; canvas not keyboard-accessible today — accept?
- **Glossary**: new term for the affordance — "entity action"? (CONTEXT.md, verb: run/open?).

## Answer

Grilling 2026-10-08. Q1 user override (whole clickable chip); Q2–Q4 accepted as recommended.

- **Chip = the action.** When the record has a visible action the whole chip becomes clickable: `<div role="button" tabindex="0">` with click + Enter/Space handlers (a nested real `<button>` for unlink with `@click.stop` — chip can't be a literal `<button>` then). No visible action → plain chip, no affordance. Unlink `×` keeps its slot on the right when editing; in read-only the Details panel never opens, so the chip question is edit-mode only.
- **Read-only canvas click runs the action.** Fact: readOnly disables selection (`userSelectAction: 'NONE'`), Details/chip never appear — so a single click on a shape whose entity has a visible action runs it (url → `window.location`, same tab; modal → `mountAction('openLinkedEntity', {type,id})`). Non-actionable shapes: unchanged tooltip-only behavior. Actionable shapes get `cursor: pointer` from the style function (discoverability without hover text).
- **One template per field.** Record-aware closures cover per-type differences inside one modal; internal registered action name `openLinkedEntity`. No per-type action config.
- **A11y bar:** chip role=button focusable, Enter/Space activate, `aria-label` from the template's label (string-resolvable) else fallback string from translations ("View linked entity"). Canvas stays mouse-only — consistent with the rest of the editor.
- **Glossary:** CONTEXT.md gains **entity link action** (verb: *run*). "Link action" avoided — link/unlink are the binding verbs already.
