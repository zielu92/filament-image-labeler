## Question

Pin the editor-side spec once the return contract exists:

- **Affordance**: entity chip clickable as a whole (cursor + hover), or trailing icon (arrow-top-right) next to unlink? Both actions visible at once (open | unlink) — order and hit areas?
- **Read-only canvas**: linked shape click → run its action instead of select; unlinked shapes do nothing? Any visual hint that a shape is actionable in view mode (pill underline, pointer cursor)? Does it apply per-shape or the whole image?
- **Resolution contract**: `resolveEntities` payload gains per-ref action data — `url` for the link case (server-evaluates the developer closure at mount: safe? needs record loaded → already loaded for display ✓). Template-Action case: no url; chip click → `mountAction('openEntity', {type,id}, {schemaComponent})` — server re-validates `{type,id}` against `linkableTo()` allow-list and record existence (trust boundary).
- **Staleness**: url cached in entityCache at mount; entity renamed/record changed mid-session → click goes to stale href? Accept and document, or re-resolve on click (one extra RPC)?
- **Keyboard/a11y**: chip as `<button>`/`<a>` focusable, Enter activates; read-only canvas shapes are not keyboard-focusable today — acceptable?
- **New term**: what do we call the affordance in CONTEXT.md (entity action? "view link"?).
