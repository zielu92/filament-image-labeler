## Question

Can a developer-returned Filament Action be mounted per-record from the ImageLabel field's Livewire host (modal, schema, url, closure-injected record), or is delegation fragile?

## Answer

Verified against vendor (Filament 5.9 / Livewire 4.4):

- **Closure injection works**: `Action::resolveDefaultClosureDependencyForEvaluationByName` (vendor/filament/actions/src/Action.php:567-583) injects `arguments`, `data`, `record`, `model`, `livewire`, … by parameter name into mounted-action closures.
- **Arguments reach the action**: `mountAction(string $name, array $arguments, array $context)` stores them per mounted action (vendor/filament/actions/src/Concerns/InteractsWithActions.php:136-148); `->mountUsing(fn (Action $action, array $arguments) …)` sees the client-passed `{type,id}`.
- **Record binding is table-only**: mounted context `recordKey` resolves through `getTableRecord()` (InteractsWithActions.php:715-719) — not available on a plain form host. Record must be set manually: `->mountUsing(fn (Action $action, array $arguments) => $action->record(resolve($arguments)))`, after which every config closure (`schema`, `modalHeading`, `modalContent`, `action`, `url`) receives `$record`.
- **No config-copy API**: mounting a *freshly constructed* developer Action by name is impossible (actions resolve from `cachedActions` by registered name); copying ~10 config properties from a per-record instance onto a registered wrapper is a fragile delegation hack.

**Consequence for the design**: the supported shape is a *template Action registered once* whose closures are record-aware (they receive `$record`), mounted with the record injected from `{type,id}` args — NOT a per-record Action object returned from a closure. A per-record closure may still return URL strings (client-side `<a href>`), which needs none of this machinery.
