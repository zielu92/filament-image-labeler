## Question

How does the user find and pick an entity when a field allows several types (Person, Building, …) whose display strings differ ("first last" vs a name column)?

Settle:

- what clicking a result does immediately: bind + show pill? does binding auto-fill the free-text label (coexist rule: label stays, but first bind could seed label if empty)?

## Answer

Resolved by grilling 2026-10-07 (user picked inline-first; wf-001 facts: Filament's Select *is* the select2-like combobox — no new lib needed; inline via child schema = wf-001 option A, costs one `dehydrated(false)` + value-forward event, not hand-rolled dropdown).

- **Form factor: inline.** Native searchable `Select` embedded in the Label Details panel (field child schema, wf-001 option A), same interaction feel as the label text input. Modal only if a flow genuinely needs one (record creation — wf-003's question). No third-party combobox (select2/Choices/TomSelect) — Filament's `selectFormComponent` JS covers it.
- **Single box, grouped results:** one search across all linkable types, options grouped by type (`optgroup`); type badge/label per row. No type-switch-first step.
- **Binding needs an active shape:** bind UI disabled when nothing selected; never silently fall back to the label's first shape.
- **Label seeding:** on first bind, fill empty `label` with the record display string; never overwrite an existing label.
- **Marker: additive.** Label chip stays as-is; entity renders as its own appended marker (pill/row) in the Details panel. Chrome itself → ticket wf-008.
- **Unbind: explicit only.** Unlink button; no implicit unbind when editing/rebinding (replacing requires the user to pick another record in the now-populated Select).
