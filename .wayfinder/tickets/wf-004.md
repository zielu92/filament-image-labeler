## Question

Name the thing before building it. What do we call a shape bound to an Eloquent record, and its inverse? Candidates seen so far: "entity link", "tagged record", "linked entity", "annotated entity" (conflicts with annotatable model — the picture's owner is already the *annotatable*).

Settle:
- term(s) for: the binding, the bound record, the picker UI, the API methods
- does it belong in CONTEXT.md glossary (yes if user-facing; align wording with existing entries: Annotation, Annotation suggestion, Apply)
- verb choice: "link"/"attach"/"bind" — consistent across method names, translations, docs

Use /domain-modeling; update CONTEXT.md as part of resolution.

## Answer

Grilling 2026-10-07, all recommendations accepted. Recorded in CONTEXT.md (5 new entries):

- **Entity link** — root association; verb is *link* (Link/Unlink). Field API keeps `linkableTo()`. Rejected: tag (collides with label practice + string-y), bind (Laravel DI noise), reference (stiff UI copy).
- **Linked entity** — the record a link points at; the *thing depicted*. Explicitly not the annotatable (image owner) — glossary disambiguates both directions. Rejected: subject (HTML/Livewire noise, and shapes can be linked-but-unlabeled).
- **Entity picker** — the inline search control (wf-002's mechanism). Name pins the "no modal" rule: a "modal" naming would have leaked the rejected option back into the language.
- **Entity chip** — the Details-panel marker. _Avoid_: pill, badge.
- **Label** — added as disambiguator: free text used for grouping/coloring, deliberately not an entity link. (Term was load-bearing in existing entries but never defined.)

Method names (`linkableTo`, `creatable`, `searchBy`) stay out of CONTEXT.md — build vocabulary lives in README/docs. If wf-007 adds entity refs to AnnotationSuggestion, the **Annotation suggestion** entry gets sharpened there, not preemptively.
