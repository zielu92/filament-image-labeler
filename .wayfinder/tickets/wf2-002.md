## Question

Charting settled the user wants `Action | string | null`, but wf2-001 proved a *fresh per-record Action object* cannot be mounted cleanly. Choose the actual API:

(a) **Template Action + record closures**: `->entityAction(Action::make('viewPlace')->schema(fn (Model $r) => …)->url(fn (?Place $r) => $r->placeUrl()))` — registered once, framework injects `$record` (mountUsing from `{type,id}`). Non-null `url` → navigate same tab; else modal from the Action's own config. Union semantics live INSIDE the Action object. Risk: which config surface do we support (documented subset: url, schema, content, heading, label, icon, color, modal width…).

(b) **URL-only v1**: `->entityAction(fn (Model $r): ?string)`; modals = developer's own page opens one (query param). Ship now; Action path becomes a future ticket.

(c) **Both separately**: URL closure for links AND template Action for modals; developer picks one method.

Decide: shape, supported Action config subset, name/registration (`entityAction` field method + registered `openEntity` wrapper action name), guard rules (type must be in `linkableTo()`, record must exist → else treat as null), and what `null` record-closure returns per click.

## Answer

Grilling 2026-10-08 — all recommendations accepted.

- **Contract: template Action.** `->entityAction(Action::make(...))` registered once (cached by name under an internal `openLinkedEntity` key). `->url(...)` non-null for a record → client navigates same tab (native CanOpenUrl, no modal); modal config (`->schema()`, `->modalHeading()`, …) → in-editor modal. The wrapper's `mountUsing` binds the record from the click's `{type,id}` args, so every developer closure receives `$record` (injection verified in wf2-001). Per-record hiding via `->visible(fn ($record) => …)`.
- **Resolution & guards:** `resolveEntities` payload gains per-ref `visible` (bool) + `url` (?string), computed server-side by evaluating the template's `visible()`/`url()` closures against the already-loaded records (EvaluatesClosures::evaluate). Clicking an Action (modal) path calls `mountAction('openLinkedEntity', {type,id})`; the server re-validates `type ∈ linkableTo()` and record existence there — the trust boundary, throwing on violation, never trusting chip state.
- **Staleness:** URL cached in `entityCache` at mount, refreshed each mount with display strings; mid-session renames → stale href until reload (documented). Modal path always fresh (record re-resolved at mount).
- **Per-record null ("whatever they want")** is expressed inside the template: `url()` closure returns null + `visible()` false for that record → plain chip, no affordance.
