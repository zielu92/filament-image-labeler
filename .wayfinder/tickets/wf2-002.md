## Question

Charting settled the user wants `Action | string | null`, but wf2-001 proved a *fresh per-record Action object* cannot be mounted cleanly. Choose the actual API:

(a) **Template Action + record closures**: `->entityAction(Action::make('viewPlace')->schema(fn (Model $r) => …)->url(fn (?Place $r) => $r->placeUrl()))` — registered once, framework injects `$record` (mountUsing from `{type,id}`). Non-null `url` → navigate same tab; else modal from the Action's own config. Union semantics live INSIDE the Action object. Risk: which config surface do we support (documented subset: url, schema, content, heading, label, icon, color, modal width…).

(b) **URL-only v1**: `->entityAction(fn (Model $r): ?string)`; modals = developer's own page opens one (query param). Ship now; Action path becomes a future ticket.

(c) **Both separately**: URL closure for links AND template Action for modals; developer picks one method.

Decide: shape, supported Action config subset, name/registration (`entityAction` field method + registered `openEntity` wrapper action name), guard rules (type must be in `linkableTo()`, record must exist → else treat as null), and what `null` record-closure returns per click.
