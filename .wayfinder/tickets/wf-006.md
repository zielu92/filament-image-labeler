## Question

Round-1: first-class `linkable_type`/`linkable_id` columns, metadata untouched, dangling links nulled via trait/observer. Now pin the contract:

- migration: nullable columns + index on `(linkable_type, linkable_id)`; naming (`linkable_*` vs `entity_*` vs term from wf-004); how existing installs upgrade (publishable migration? auto?)
- syncAnnotations(): link fields in `$data` items; how is a link *removed* — explicit null in payload vs absent key (current sync = updateOrCreate on annotation_id; absence semantics must not silently drop links)
- Livewire state shape: per-shape `entity: {type, id} | null` alongside `label`/`color`; hydration from DB rows (Annotation model → field state) — where does display string come at render time (eager load per page? N+1 guard?)
- HasAnnotations additions: `links()`? morphMany per type? deletion cleanup from BOTH sides: annotatable model deleted (existing) and linked model deleted (new — observer on which models? registration mechanics for arbitrary linkables)
- Annotation model fillable/casts/relationship updates

## Answer

Grilling 2026-10-08 — all four recommendations accepted.

- **Columns:** `entity_type` / `entity_id`, nullable, index on `(entity_type, entity_id)` for reverse lookups; migration `add_entity_columns_to_annotations_table`, autoloaded (no publish), ships in next minor. `Annotation::entity(): MorphTo`.
- **Cleanup:** marker trait `LinkableEntity` (README API name; CONTEXT.md untouched). On the *linked* model: `deleted` hook nulls `entity_type/entity_id` of pointing annotations; also exposes `linkedAnnotations(): MorphMany`. Models without the trait: links dangle; editor renders anyway per wf-005, chip falls back to class basename.
- **syncAnnotations contract:** items may carry flat `entity_type`/`entity_id`; explicit null clears, absent key leaves existing link untouched (updateOrCreate semantics); half-link (type xor id) coerces to full null. Documented: apps syncing from the editor always send both keys.
- **Chip display:** package resolves — editor batches unique `{type,id}` refs on mount through one renderless `ExposedLivewireMethod` (same RPC path as the picker), display strings cached in `metaCache`; uses wf-003 display convention server-side. Consumers supply no labels.
- **State shape:** per-shape `entity: {type, id} | null` inside the field array (stays under `data.<field>`, no sibling pollution); consumer mapping copies it to the flat sync keys per the contract. `metadata` semantics unchanged.
- Annotation model: `entity_*` added to fillable; casts plain strings/ints.
